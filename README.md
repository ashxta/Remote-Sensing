# Remote Sensing-Based Detection of Land Degradation and Vegetation Dynamics Using Multi-Temporal Geospatial Data

B.Tech CSE major research project. **Phases M1–M4 complete.**

> ### Data status — read first
> The repository runs on a **SYNTHETIC** dataset generated by
> `demo/make_synthetic_data.py`. **Synthetic data are for development and
> testing and do not represent actual remote-sensing findings.** They are not
> real observations and must not be interpreted as real-world research
> results. No output in this repository measures Assam, Northeast India, or
> any real location. M1–M5 develop and validate the research framework; M6
> integrates real remote-sensing data; M7 performs real-world experiments.

---

## 1. Research objective

Detect and characterise land-degradation and vegetation-dynamics signals in
multi-temporal NDVI stacks, and test whether **multi-temporal trajectory
analysis improves detection and interpretation of land degradation compared
with conventional trend analysis**.

Conventional practice answers one question — *is there a significant negative
monotonic trend?* — which cannot distinguish a degrading pixel from a cyclic
one in a low phase, or from a disturbed pixel that has since recovered. This
project builds the additional temporal evidence (climate-adjusted trends,
spectral periodicity, structural breakpoints, post-disturbance recovery),
turns it into per-pixel features, and measures whether that evidence actually
carries information a classifier can use.

## 2. Methodology

```
NDVI + rainfall time series per pixel
      │
      ├── monotonic trend        Mann-Kendall (tie- and autocorrelation-corrected)
      │                          + Theil-Sen slope
      ├── climate adjustment     RESTREND (NDVI ~ rainfall + time, joint fit)
      ├── periodicity            spectral band enrichment + AR(1) surrogate test
      ├── disturbance            exhaustive two-segment breakpoint + Chow test
      └── recovery               trough, magnitude, fraction, duration, slope
      │
      ▼
45 engineered features in 7 documented groups
      │
      ├── analytical trajectory classes (rule-based, configurable)
      └── classifiers: Random Forest / 1D CNN
      │
      ▼
spatial block cross-validation → metrics, uncertainty, explainability
```

## 5. Statistical methods and feature engineering

M2 turns the M1 estimators into a reusable research framework. The flow, and
the module that owns each step, is:

```
configuration (config.py)
  -> dataset + validity checks (dataset.py)
  -> quality control (quality.py)
  -> temporal analysis (timeseries.py, recovery.py)
  -> feature engineering (features.py)
  -> trajectory categories (trajectory.py)
  -> feature-set selection (config.FeatureConfig / AblationConfig)
  -> model + spatial validation (validation.py)
  -> ablation (ablation.py), sensitivity (sensitivity.py),
     temporal holdout (holdout.py)
  -> metrics, predictions, figures, georeferenced layers
     (reproducibility.py, geo.py, maps.py, research_figures.py)
```

`run_m2_experiments.py` is the only place that orders these steps; it holds no
analysis logic, so an experiment is defined by its `Config` alone. Every M2
setting lives in `Config.research` and is snapshotted to
`results/<id>/config/config.json`, which `--config` replays.

### Feature engineering

`features.build_feature_table` produces 47 columns (45 modelling features plus
2 diagnostics) in seven documented groups. Every column has a `FeatureSpec`
with a description and the estimator it came from, exported as
`metrics/feature_dictionary.csv` in every run.

| Group | Features |
|---|---|
| vegetation | `mean`, `median_ndvi`, `minimum_ndvi`, `maximum_ndvi`, `std`, `cv`, `amp`, `sen`, `ols_slope` |
| trend | `mk_z`, `mk_p_value`, `mk_tau`, `mk_significant`, `trend_direction` |
| rainfall | `rain_mean`, `rain_std`, `rain_cv`, `rain_sen`, `rain_ndvi_correlation` |
| restrend | `restrend`, `restrend_p_value`, `restrend_r2`, `restrend_beta`, `restrend_significant` |
| cyclicity | `cyc_score`, `cyc_enrichment`, `cyc_period`, `cyc_band_power`, `cyc_total_power`, `cyclicity_periodic` |
| disturbance | `has_break`, `break_t`, `break_dslope`, `break_gain`, `breakpoint_index`, `breakpoint_significant`, `pre_breakpoint_level`, `post_breakpoint_minimum`, `disturbance_magnitude` |
| recovery | `has_disturbance`, `recovery_magnitude`, `recovery_fraction`, `recovery_duration`, `recovery_slope`, `recovery_status` |
| diagnostic (withheld from models) | `n_valid_ndvi`, `n_valid_pairs` |

The M1 feature block is reproduced column-for-column and unchanged; a test
enforces that M2 never drops or renames an M1 feature. `mk_z` is the
Hamed–Rao autocorrelation-adjusted statistic whenever
`TrendConfig.apply_autocorrelation_correction` is set. Feature generation is
deterministic, uses no RNG, is NaN-aware, and returns NaN (never a guess) for
pixels below the configured minimum number of observations. Descriptors that
are *undefined* because the event did not occur (no break, no disturbance) are
encoded as a neutral 0 beside an explicit `has_break` / `has_disturbance`
indicator, following the M1 policy on structural missingness.

### Trajectory classes

`Stable`, `Degrading`, `Recovering`, `Cyclic`, `Uncertain / Other` are
**analytical trajectory classes derived from NDVI shape**, not verified
land-cover classes and not proven degradation states. Cyclic does not mean
jhum; a negative trend does not prove degradation. The rules, all
configurable in `TrajectoryConfig` and exported as
`metrics/trajectory_summary.json`:

| Class | Rule (defaults) |
|---|---|
| Degrading | Sen slope < 0 **and** Mann–Kendall p < `trend.alpha` (0.05) |
| Cyclic | spectral enrichment ≥ `cyclicity.periodicity_threshold` (2.0) **and** the estimator's periodic flag |
| Recovering | disturbance ≥ `recovery.min_disturbance_magnitude` (0.05 NDVI), recovery fraction ≥ 0.80, **and** a significant structural break |
| Stable | none of the above and no significant increase |
| Uncertain / Other | core statistics not finite, or no rule matched |

Rules are evaluated in a configurable `priority` order (default
`Recovering, Degrading, Cyclic, Stable`); the first match wins. The
significance level, periodicity threshold and minimum disturbance magnitude
are **inherited from the M1 config sections**, so each parameter has one
source of truth and a sensitivity sweep over it reaches every stage.

## 6. Machine-learning methods

### Random Forest

Fixed seeds, configurable hyper-parameters (`RFExperimentConfig`) and
configurable feature sets. Reported metrics are accuracy, Cohen's kappa,
macro/weighted precision, recall and F1, per-class precision/recall/F1 with
support, and the confusion matrix — accuracy is never reported alone. Class
probabilities are saved with class-labelled columns and are described
throughout as **model confidence estimates, not certainty**. Feature
importance is impurity-based: predictive association, not causal influence.

## 7. Validation

### Spatial cross-validation

Whole square blocks of the grid are assigned to folds by a seeded permutation
(`SpatialCVConfig`: `block_size`, `n_folds`, `seed`, `buffer_blocks`). A block
is never split between folds, so train and test never share a pixel *or* a
block; `buffer_blocks > 0` additionally drops training samples within a
Chebyshev block-distance of any test block. Fold assignment depends only on
the grid size and the configuration, so it is reproducible. Metrics are
reported per fold and as mean ± standard deviation. The fold map is written
both as a figure and as a georeferenced layer.

The imputer — the only component that learns parameters — is fitted inside
each training fold and applied to the test fold. Feature engineering is
strictly per-pixel and involves no cross-pixel fitting, so it cannot leak.

**Random pixel splitting is retained only as a baseline** (`validation
_comparison.csv`), explicitly labelled optimistic, and is never presented as
spatially independent validation.

## 8. Experiments

### Ablation study

One reusable mechanism runs every cell; there are no duplicated scripts. Cells
are declared in `AblationConfig` as (id, name, feature groups) and each
strictly contains the previous one:

| Cell | Feature groups |
|---|---|
| A | vegetation |
| B | + trend |
| C | + restrend |
| D | + cyclicity |
| E | + disturbance + recovery |
| F | + rainfall (the full framework) |

Each cell saves its id, feature set, configuration, model parameters,
metrics, predictions, probabilities, confusion matrix, feature importance and
a log; the study writes `ablation_comparison.csv` and `.json`.

### Sensitivity analysis

`SensitivityConfig` declares parameter sweeps (significance level, minimum
valid observations, RESTREND minimum r², periodicity band and threshold,
breakpoint gain, recovery threshold). Each scenario re-runs the analysis
end-to-end from the raw series under a deep copy of the configuration, so the
reported spread is the full effect of the parameter. **Nothing is optimised:**
no parameter is selected by comparing test-set metrics. Results are written as
`sensitivity_results.csv/.json` and `sensitivity_scenarios.csv`.

### Temporal holdout

`holdout.py` splits the record at a configurable cutoff, materialises the two
windows as separate arrays before any estimator runs, and builds each
window's features from that window only, so no future observation can enter a
training feature (enforced by a test that corrupts the future and asserts the
historical features are unchanged). Optionally the evaluation set is also a
held-out spatial fold, separating train and test in both time and space.

**On the current synthetic data this experiment is infrastructure only.**
Synthetic pixels carry one static label for the whole record and the windows
are short, so a holdout score characterises the generator rather than
temporal generalization. Every holdout result is stamped
`meaningful_on_this_dataset: false` and ships with a `LIMITATION.txt`. Real
multi-decadal data (M6/M7) are required before any temporal-generalization
claim.

### What the synthetic runs actually show

These are properties of the development dataset and the code, not findings
about any landscape:

* Ablation macro F1 (spatial block CV, 600 samples, seed 42) runs
  A 0.978 → B 0.980 → C 0.997 → D 1.000 → E 1.000 → F 0.997. RESTREND and
  cyclicity carry the gain; the disturbance/recovery block adds nothing once
  the score is already saturated, and the descriptive rainfall block in F
  costs a fraction of a point, i.e. it behaves as noise here. The near-1.0
  ceiling reflects separability designed into the generator and is an upper
  bound, not an expected real-data score.
* Spatial block CV and the random-split baseline agree closely here because
  the generator's archetypes are assigned per pixel from smooth spatial
  fields; the gap that motivates spatial CV is expected to appear on real
  data, not on this dataset.
* The `Cyclic` rule fires on very few synthetic pixels: median spectral
  enrichment is 1.63 for the periodic archetype against 1.42 for cropland and
  1.18 for stable forest, so the default threshold of 2.0 (twice the
  white-noise level) is rarely reached. The threshold was **not** lowered to
  fit the dataset; the sensitivity sweep reports what happens at 1.5 and 3.0
  instead. The classifier still uses `cyc_enrichment` as a continuous
  feature, which is where the ablation gain at cell D comes from.

### What the M3 synthetic runs actually show

Properties of the development dataset and the code, not findings about any
landscape (600 samples, 5 spatial folds, seed 42):

* **Binary degradation detection.** The conventional Mann–Kendall/Sen rule
  already reaches 0.953 macro F1; the learned methods reach 0.995–1.000. The
  gap (+0.047) exceeds the across-fold spread, but the honest reading is that
  a monotonic trend test is *already close to sufficient* when degradation is
  a clean monotonic decline, which is how the generator builds it.
* **Where the framework actually earns its place** is the multiclass
  trajectory task, which the trend rule cannot attempt at all: basic
  vegetation features give 0.978 macro F1, the full proposed framework 0.997.
  Separating cyclic, recovering and stable trajectories is exactly what a
  monotonic test cannot do by construction.
* **The extra features do not help the binary task** (rf_basic 0.997 vs
  rf_proposed 0.995 — a difference inside the fold spread). Reporting only
  the binary number would overstate the framework; reporting only the
  multiclass number would overstate the baseline's weakness.
* **The CNN matches the engineered features** (1.000 binary, 0.997
  multiclass) given the full sample and 80 epochs, and collapses to ~0.66
  macro F1 in the reduced smoke configuration. On this dataset the learned
  representation is competitive but not superior, and it is markedly more
  sensitive to sample size and training budget.
* **Buffered spatial CV changes nothing measurable here** (macro F1 0.9967 at
  `buffer_blocks=0` vs 1.0000 at 1), so no adjacency leakage is detectable on
  synthetic data. That is a property of a generator built from smooth spatial
  fields; the check matters on real data, which is why it is reported rather
  than assumed.
* **The red-noise surrogate test flags more pixels than the enrichment
  threshold** (7.2% vs 0.5%, 93.3% agreement): the fixed threshold of 2.0 is
  the more conservative of the two rules on this dataset.

## Research-grade evaluation (M3/M4 additions)

M3 makes the evaluation research-grade: an executable leakage audit, a
like-for-like method comparison, uncertainty reporting, explainability, and a
significance test for periodicity. `run_m3_experiments.py` runs all of it.

### Experiment matrix

Four methods, one protocol — the same spatial block folds, the same samples
and the same metric code:

| Method | Representation | Learns? |
|---|---|---|
| `baseline_trend` | Mann–Kendall p + Sen slope sign | no, fixed rule |
| `rf_basic` | basic vegetation features | yes |
| `cnn_1d` | raw NDVI sequence | yes |
| `rf_proposed` | trend + RESTREND + cyclicity + breakpoint/recovery | yes |

The conventional trend rule can only answer *"is there a significant negative
trend?"*, so scoring it on a five-class problem would be rigged. Every method
is therefore evaluated on a **binary degradation-detection task** (the
like-for-like comparison), and the multiclass result is reported separately
for the methods that can attempt it. `experiment_matrix.json` states the
ranking and whether the gap over the baseline exceeds the across-fold standard
deviation — a difference smaller than the fold spread is explicitly *not*
called an improvement.

### 1D CNN

The research question is whether a model that learns from the raw sequence
beats engineered temporal features. To keep that question answerable, the
architecture is small and **fixed across the comparison** (two Conv1d +
BatchNorm + ReLU blocks, global average pooling, dropout, linear head); making
the network bigger would confound representation with capacity.

Validation uses the same spatial philosophy as the Random Forest. Each fold is
held out in turn, and within each iteration three groups are disjoint:

* **test fold** — never seen during training, normalisation or early stopping;
* **validation folds** — carved out of the *training* side (`validation_folds`),
  used only for early stopping and checkpoint selection;
* **training folds** — everything else.

Per-time-step normalisation statistics are fitted on training columns only.
Early stopping monitors validation loss with configurable patience; the best
checkpoint is saved per fold and reloaded for inference. Seeds are fixed and
inference runs under `eval()` with no gradient, so repeated runs give
identical predictions (enforced by a test). Outputs: training/validation
curves, per-fold and pooled per-class precision/recall/F1, macro and weighted
F1, confusion matrix, probabilities, confidence and uncertainty flags.

`torch` is an optional dependency — importing the module is always safe, and
the experiment matrix records the CNN as *skipped with a reason* rather than
silently dropping it.

### Uncertainty

Three complementary measures, because the maximum probability alone hides the
shape of the distribution:

| Measure | Meaning |
|---|---|
| `confidence` | maximum class probability |
| `margin` | top probability minus runner-up — catches contested predictions a high top score would hide |
| `entropy` | Shannon entropy normalised by log(n_classes) |

A prediction is flagged `uncertain` when confidence falls below
`confidence_threshold` (0.60) **or** margin falls below `margin_threshold`
(0.15). Both are reporting conventions, not rules validated against ground
truth.

> **These are model confidence estimates, not certainty.** Random Forest
> probabilities are tree-vote fractions and CNN outputs are normalised logits;
> both are typically miscalibrated, and neither carries information about
> sensor artefacts, label error, or land-cover types absent from training.
> They are useful for *relative* ranking — which predictions the model itself
> found marginal.

The summary reports accuracy on the confident subset against the flagged
subset, and sets `confidence_is_informative: false` when flagged predictions
are not actually worse. An uninformative confidence measure is surfaced, not
hidden.

### Explainability

Three views, because each fails differently:

* **impurity importance** — cheap, but biased towards high-variance features
  and computed on training data;
* **permutation importance** — macro F1 drop when a feature is scrambled,
  measured on **held-out spatial folds**; this is the one to quote;
* **SHAP** — optional per-sample attributions with per-class direction;
  skipped cleanly when the package is absent.

> Importance is **predictive association inside a fitted model, not causal
> influence**. Correlated features (NDVI mean and median, for example) share
> credit arbitrarily.

### Cyclicity significance

Enrichment answers "how much more band power than white noise", but
vegetation series are autocorrelated, and autocorrelation alone pushes power
to low frequencies — so a fixed enrichment threshold has no stated
false-positive rate. `timeseries.cyclicity_significance` attaches an explicit
null:

* `null="ar1"` (default) — an AR(1) process is fitted per pixel and simulated
  `n_surrogates` times; surrogates share the pixel's persistence but contain
  no cycle. This is the standard red-noise test for spectral peaks.
* `null="shuffle"` — random permutation, i.e. the white-noise null the
  enrichment statistic already assumes; provided for comparison.

The empirical p-value is the conservative rank estimator
`p = (1 + #{surrogate ≥ observed}) / (1 + n)`, never zero.

**Phase randomisation is deliberately not offered.** Theiler surrogates
preserve the amplitude spectrum exactly, so any spectrum-derived statistic —
including this band fraction — is identical for every surrogate and the test
returns p = 1 by construction. It is the wrong tool for this statistic.

Measured behaviour of the test (200 series, 99 surrogates, α = 0.05):

| Series | AR(1) null | white-noise null |
|---|---|---|
| white noise | 1.5% flagged | 2.5% flagged |
| strong 6-step cycle | 100% | 100% |
| weak 6-step cycle | 2.5% | 6.0% |
| **AR(0.7) red noise** | **3.0%** | **22.0%** |
| linear trend | 1.5% | 3.0% |

The red-noise row is the reason the AR(1) null exists: judged against white
noise, ordinary persistence looks periodic four times more often than the
nominal rate.

> A small p-value means the band concentration is unlikely under the stated
> null. **It says nothing about the cause.** Rotational cultivation,
> plantation harvest cycles, fire-regrowth cycles and multi-year climate
> oscillation all produce periodicity. **Periodicity is not jhum.**

### Leakage audit

Every claim about leakage is an executable assertion re-evaluated on every
run and saved to `metrics/leakage_audit.json`; a failure raises and stops the
experiment rather than publishing a number.

| Check | Question |
|---|---|
| `spatial_sample_overlap` | do train and test share a sample? |
| `block_purity` | is a spatial block split across folds? |
| `buffer_separation` | is any training block inside the configured buffer? |
| `temporal_separation` | do historical indices all precede the cutoff? |
| `no_lookahead` | corrupt every observation after the cutoff — do the historical features change? |
| `label_leakage` | is any model input named after, or numerically identical to, the target? |
| `preprocessing_isolation` | was the imputer fitted on test samples? |
| `ablation_isolation` | does a cell contain an undocumented or duplicated feature? |
| `ablation_feature_groups` | does a cell resolve to exactly its declared groups? |

Each check is tested on both a clean and a deliberately contaminated input,
so it can actually fail. Note the honest position at `buffer_blocks = 0`:
train and test share no pixel and no block, but blocks that touch across a
boundary remain spatially autocorrelated. The runner therefore reports a
**buffer sensitivity** table (`buffer_blocks` 0 vs 1) so the size of that
effect is measured rather than assumed.

### Temporal generalization

`run_temporal_holdout` trains on a historical window and evaluates on a later
unseen one, with a configurable cutoff. Windows are materialised as separate
arrays before any estimator runs, and the no-lookahead check is re-run on the
holdout itself. Optionally the evaluation set is also a held-out spatial fold,
separating train and test in both time and space.

**On synthetic data this remains infrastructure only:** pixels carry one
static label for the whole record and the windows are short, so a holdout
score characterises the generator, not temporal generalization. Results are
stamped `meaningful_on_this_dataset: false`.

## 11. What must change for real satellite data

**Nothing in the analytical pipeline.** Everything downstream of
`data_source.py` consumes a `StandardizedDataset` and nothing else, so M6
means writing one `DataSource` subclass:

```python
class LandsatCHIRPSSource(DataSource):
    name = "landsat_chirps"

    def load(self) -> StandardizedDataset:
        ...  # acquire, harmonise, composite, align
        return StandardizedDataset(ndvi=..., rain=..., georef=...,
                                   times=..., truth=..., metadata=...)

# then, unchanged:
prepare_experiment(cfg, source=LandsatCHIRPSSource())
```

The contract that subclass must satisfy is machine-readable
(`data_source.REAL_DATA_REQUIREMENTS`, saved into every run as
`config/real_data_requirements.json`) and enforced on load:

| Requirement | Why it matters |
|---|---|
| Aligned (T, H, W) cubes, one grid, one CRS, one time axis | the pipeline never reprojects; misalignment would pair a pixel with another pixel's rainfall |
| NaN for every masked observation (cloud, shadow, SLC-off, scene edge) | a sentinel such as −9999 or 0 is a valid number to a regression |
| Physical units (NDVI scale factor applied; stated rainfall units) | scaled integers pass every shape check and corrupt every threshold |
| Sensor harmonisation across Landsat 5/7/8/9 and Sentinel-2 | an unharmonised sensor change is a step that breakpoint detection reports as a real disturbance |
| One compositing rule for the whole record | a changing composite window changes the phenological stage measured, which appears as a trend |
| Declared, ordered time axis, one entry per band | periods and slopes are expressed in time steps |
| Study-area boundary supplied as configuration | no analytical function may assume a region |
| Recorded QA/cloud-mask provenance | missingness is a covariate: a mask change alters trend detectability |
| Reference labels from independent ground or ancillary data | labels derived from the same NDVI series are circular |
| Rainfall resampled onto the NDVI grid and accumulation window | RESTREND regresses NDVI on rainfall pixel by pixel |

Two additional expectations for real data, already handled by the code but
worth stating: valid-observation counts will be far lower and spatially
uneven (the quality gate and `n_valid_ndvi` diagnostic exist for this), and
degradation will be a **rare class**, so class imbalance handling
(`RFExperimentConfig.class_weight`) becomes load-bearing rather than optional.

## Scientific assumptions and interpretation limits

These are stated in code docstrings and must be carried into the report.

1. **Periodicity is not attribution.** `cyclicity` detects oscillation
   within a configurable period band. Multi-year climate oscillation,
   plantation harvest rotation and fire-regrowth cycles all produce the
   same spectral signature as rotational cultivation. Periodicity is
   *consistent with* cyclical land use; it is not evidence of any specific
   practice. Attribution requires independent ground data.
2. **RESTREND does not prove human causation.** A significant negative
   climate-adjusted trend means vegetation underperformed *relative to what
   rainfall predicts*. Unmodelled climate variables (temperature,
   radiation, rainfall timing, antecedent soil moisture), fire, pests and
   land-cover conversion produce the same signature.
3. **RESTREND is conditional on a real rainfall relationship.** Where the
   NDVI~rainfall regression is weak, insignificant, or negative under the
   water-limited assumption, the adjusted trend is *not* climate-corrected
   and must be reported as an uncorrected trend. The `restrend_valid` layer
   marks where the correction is interpretable (83.8% of pixels in the
   current synthetic run).
4. **Trend detectability is bounded.** Wessels et al. (2012) show that
   NDVI must fall substantially before monotonic tests reach significance.
   Absence of a significant trend is not evidence of absence of change.
5. **Breakpoint significance is selection-adjusted.** The break position is
   chosen by maximising fit, so a naive Chow p-value is optimistic. A
   Bonferroni adjustment over candidate positions is applied; this is
   conservative. The exact remedy (sup-F with Andrews critical values) is
   **still outstanding** — M2 did not implement it and it is carried to M3.
6. **Structural vs unknown missingness.** Recovery and break descriptors
   are *undefined* for pixels with no disturbance, not unknown. They are
   encoded with explicit `has_disturbance` / `has_break` indicators and
   neutral zeros. This is explicit encoding of a known state, not
   imputation.
7. **This is not an SDG 15.3.1 assessment.** The productivity map is drawn
   *in the style of* the UNCCD SDG 15.3.1 productivity sub-indicator. It has
   not been computed as an official 15.3.1 assessment and must never be
   reported as one: a complete assessment additionally requires land-cover
   change and soil organic carbon, uses the UNCCD's own baseline and
   reporting periods, and runs on real observations. None of those
   conditions is met here.
8. **Synthetic-data ceiling.** Classification metrics near 0.99 reflect the
   separability designed into the synthetic generator. They are an upper
   bound and must not be quoted as expected real-data performance.
9. **The periodicity threshold is an enrichment, not a fraction.**
   `timeseries.cyclicity` returns *enrichment* — band power divided by its
   flat-noise expectation — which is 1.0 under white noise regardless of band
   width or record length. `CyclicityConfig.periodicity_threshold` is
   compared against that. Its default was corrected in M2 from `0.35` (a raw
   band-fraction value left over from the pre-enrichment scoring, which
   labelled essentially every pixel periodic) to `2.0`, matching the
   estimator's own default and the M1/M2 test suites.

## Data-quality policy

Missing observations are quantified and flagged, never silently filled.
Interpolation is off by default; when enabled it fills only interior gaps
up to `max_interpolation_gap` steps and never extrapolates. Quality flags
are written as a georeferenced layer alongside the results.

| Flag | Meaning |
|---|---|
| 0 | OK |
| 1 | insufficient valid observations |
| 2 | missing fraction above threshold |
| 3 | constant series (no signal) |
| 4 | no values inside the physical NDVI range |
